---
name: Guest-first data migration
description: Rules for allowing YOKI YOKI users to begin without an account and safely back up their data later.
---

Users can start YOKI YOKI without a Clerk account. Their core progress, shop purchases, equipment slots, and item placement settings remain on the current device. The App Store iOS release remains guest-only until production authentication-email delivery has been proven reliable; web and Android may continue to offer optional login and cloud backup.

**Why:** App Review repeatedly treated exposed registration as a core feature and rejected the app when its reviewers did not receive Clerk verification emails, even when a demonstration mode was documented. Any visible auth state remains reviewable, so iOS must not advertise or expose authentication until its email delivery can be demonstrated. Browser acquisition still benefits from optional accounts, but an existing account's saved profile and settings must never be silently replaced by data from a shared device.

**How to apply:** On iOS, route first use directly into local onboarding and do not show login, registration, verification codes, demo credentials, or cloud-backup prompts. Bypass the authentication provider itself so an update over an authenticated build cannot restore a cached session, token, or cloud sync behind the guest-only UI. Keep all core features available from local data. On platforms that expose auth, keep guest start prominent, localize actionable errors, state password requirements before submission, and complete client-trust or second-factor states instead of stopping at an error. At first login, retain account settings as authoritative, union inventories and append-only histories, keep furthest progress, then back up the merged state. Never treat a cloud timeout or failed pull as confirmation that the account is empty. Clearly state that local-only data cannot be recovered after app/browser-data deletion or a device change.
