## GitHubと返送bundleの違い

この環境でも通常のGit pushに使える認証情報がなく、元の5コミットのGitオブジェクトをそのままGitHubへpushできない。GitHub連携では統合後のアプリ・テスト・公開進捗文書を候補へ保存する。内部HOME作業メモと詳細なApp Store審査履歴の公開は自動承認審査で拒否されたため、今回の `.agents/memory` と `artifacts/mobile/APP_REVIEW_NOTES.md` の更新は公開対象から除外し、返送用履歴に保持する。公開側は以前の文書を維持する。元のコミットID・親関係を保持したローカル統合履歴は、公開候補と一緒に返送用Git bundleへまとめる。

したがって、候補に同じソースが保存されたことと、元の5件のSHAがGitHubの祖先になったことを混同しない。返送先と公開候補のtreeは内部メモ・審査文書の5ファイルだけ異なり、アプリ・テスト・公開進捗文書は一致する。返送bundleのマニフェストに記録された統合先はReplitの `73c7124` と公開候補の両方を祖先に持つ。Replitに既存の `73c7124` と `113619b09ece26900a46f1e63bfdcd4883d53528` があれば、認証不要で受け取れる。ファイルを丸ごと上書きしたり、mainをresetしたりする必要はない。
